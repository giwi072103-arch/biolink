# biolink

Кастомизируемая биолинк-страница: Liquid Glass дизайн, фон-фото/видео с размытием,
30+ иконок соцсетей и игр, музыкальный плеер, регистрация через Telegram-бота.

## Стек

- **Backend:** Express + JSON-файл вместо БД (без нативных зависимостей — собирается
  без проблем и в Termux, и на Railway)
- **Auth:** JWT, пароли хешируются bcryptjs, код регистрации выдаёт Telegram-бот (Telegraf)
- **Frontend:** без сборщика — чистый HTML/CSS/JS, поэтому редактировать можно прямо
  в GitHub-редакторе
- **Иконки:** подгружаются на лету с Iconify (`simple-icons`), ничего не хранится в репо

## Запуск локально / в Termux

```bash
npm install
cp .env.example .env
# впиши BOT_TOKEN (получить у @BotFather) и SITE_URL
npm start
```

Сайт поднимется на `http://localhost:3000`.

## Настройка бота

1. В Telegram напиши **@BotFather** → `/newbot` → получишь `BOT_TOKEN`.
2. Открой файл **`.env`** (создаётся из `.env.example`, см. выше) и впиши токен в строку:
   ```
   BOT_TOKEN=вставь_сюда_свой_токен
   ```
   Это единственное место, куда кладётся токен — сервер сам подхватит его при старте
   (`server/index.js` → `process.env.BOT_TOKEN`). В сам код токен никогда не пишется.
3. Открой **`public/js/config.js`** и укажи `BOT_USERNAME` (юзернейм бота без `@`) —
   нужен для кнопки «Открыть бота» и диплинков на страницах регистрации/сброса пароля.

## Как теперь работает регистрация

Логин, пароль и Telegram указываются сразу на сайте — бот только подтверждает и привязывает аккаунт к тому, кто написал:

1. На `/register.html` пользователь вводит логин, пароль и свой Telegram (username или числовой ID).
2. Сервер создаёт «отложенную» регистрацию (`pendingRegistrations` в базе) и выдаёт 6-значный код на 15 минут.
3. Страница показывает код и кнопку «Открыть бота и подтвердить» — это диплинк вида
   `https://t.me/BOT_USERNAME?start=confirm_123456`, бот получает код автоматически.
   Если диплинк почему-то не сработал, можно вручную написать боту `/confirm 123456`.
4. Бот создаёт аккаунт, привязывает `telegramId` реального отправителя (а не просто введённого на
   сайте username — это финальная проверка) и кладёт одноразовый JWT в `claims`.
5. Страница регистрации в это время поллит `/api/auth/register/claim/:code` раз в 2 секунды —
   как только код подтверждён, токен забирается и человека сразу кидает в `/dashboard.html`.

## Сброс пароля через бота

1. Пользователь пишет боту команду `/reset`.
2. Бот находит аккаунт по `telegramId` отправителя, генерирует код на 15 минут и присылает его в чат
   вместе со ссылкой на `/reset.html`.
3. На `/reset.html` человек вводит логин, этот код и новый пароль — пароль обновляется.

Есть нюанс: `/reset` работает только если Telegram, из которого пишут, уже привязан к аккаунту
(то есть регистрация была подтверждена именно с него). Отвязать/сменить Telegram аккаунта
через бота сейчас нельзя — это в списке «что доточить» ниже.

## Деплой на Railway

1. Залей проект в GitHub-репозиторий.
2. В Railway: New Project → Deploy from GitHub repo.
3. В переменных окружения (Variables) добавь `BOT_TOKEN`, `JWT_SECRET`, `SITE_URL`
   (это будет твой `*.up.railway.app` домен или кастомный).
4. Railway сам подхватит `npm start`. Порт слушается через `process.env.PORT` — трогать не нужно.

⚠️ Важно: файлы (`data/db.json`, загрузки в `uploads/`) хранятся на диске контейнера.
На Railway это эфемерное хранилище — при редеплое всё обнулится. Для продакшена
стоит подключить Railway Volume (Settings → Volumes, примонтировать на `/data` и `/app/uploads`)
или перейти на внешнее хранилище (S3-совместимое, например Cloudflare R2) для аплоадов.

## Структура — что где лежит и что куда класть

```
biolink/
├─ .env                       ← СЮДА кладёшь BOT_TOKEN, JWT_SECRET, SITE_URL (сам создаёшь из .env.example)
├─ .env.example                 шаблон переменных окружения, копируется в .env
├─ package.json                 зависимости и `npm start`
├─ data/
│   └─ db.json                  создаётся автоматически при первом запуске — вся "база" в одном файле
├─ uploads/                     сюда сервер сохраняет загруженные фоны и треки (создаётся сам)
│
├─ server/                      ВСЁ, что относится к бэкенду
│   ├─ index.js                 точка входа: поднимает express + запускает бота, если задан BOT_TOKEN
│   ├─ bot.js                   Telegram-бот: подтверждение регистрации (/confirm) и сброс пароля (/reset)
│   ├─ db.js                    чтение/запись data/db.json
│   ├─ middleware/
│   │   └─ requireAuth.js       проверка JWT на защищённых роутах
│   ├─ utils/
│   │   ├─ auth.js              подпись и проверка JWT
│   │   └─ defaultProfile.js    профиль "по умолчанию" для новых аккаунтов
│   └─ routes/
│       ├─ auth.js              /api/auth/register/start, /claim/:code, /login, /reset/confirm
│       ├─ profile.js           /api/profile/me (свой профиль), /api/profile/:username (публичный)
│       └─ upload.js            /api/upload/background, /api/upload/music
│
└─ public/                      ВСЁ, что отдаётся в браузер как есть, без сборки
    ├─ index.html                лендинг
    ├─ login.html                вход по логину/паролю
    ├─ register.html             регистрация (логин+пароль+telegram → код → подтверждение в боте)
    ├─ reset.html                сброс пароля (логин + код из /reset в боте + новый пароль)
    ├─ dashboard.html            редактор профиля (после входа)
    ├─ u.html                    шаблон публичной страницы — отдаётся на любой /u/:username
    ├─ css/
    │   └─ style.css             вся дизайн-система: Liquid Glass, токены цветов, анимации
    └─ js/
        ├─ config.js             СЮДА кладёшь BOT_USERNAME (юзернейм бота без @)
        ├─ api.js                обёртка над fetch + все вызовы к /api/*
        ├─ icons.js               каталог иконок соцсетей/игр (Iconify, ничего скачивать не надо)
        ├─ scene.js                фон: блобы, видео/картинка, курсор-свечение
        ├─ particles.js             canvas-частицы (включаются тумблером в теме)
        ├─ dashboard.js              вся логика редактора — единственный файл, который дёргает все API разом
        └─ profile.js                 рендер публичной страницы по /u/:username
```

Если правишь дизайн — тебе почти всегда нужен только `public/css/style.css`.
Если правишь логику регистрации/пароля — `server/routes/auth.js` (сервер) и `server/bot.js` (бот) вместе,
плюс `public/register.html` / `public/reset.html` на фронте.
